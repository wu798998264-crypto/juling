# 聚灵 S1.0.6 · macOS 1.4.0

与已发布的 Windows S1.0.6 使用同一份应用源码：
`d03e4695513a62061d3fce457eef887bc6dd93bf`。
功能基线为上游正式版 v1.4.0，保留聚灵界面、账号兼容、独立更新与冷却安全策略。

## 下载选择

- `Juling_1.4.0_aarch64.dmg`：Apple 芯片 Mac。
- `Juling_1.4.0_x64.dmg`：Intel Mac。
- `Juling_1.4.0_universal.dmg`：同时包含两种架构。

打开 DMG，将“Juling.app（聚灵）”拖入 Applications。支持 macOS 12 及更新版本。
Mac 内部可执行文件与应用目录使用 Juling，避免中文文件名触发 CoreFoundation 查询崩溃；
界面和显示名称仍为聚灵。安装包保留聚灵图标和维护者链接，
不含原版广告。离线许可与来源说明随包保留。

## 签名与验证

按照玄念打包技能的无开发者证书方案，这批 Mac 包使用 **ad-hoc 临时签名，未进行 Apple 公证**。
Tauri 更新签名沿用聚灵现有公钥，用于验证后续更新包；它不能替代 Apple Developer ID。
首次启动可能需要用户按 [Apple 官方说明](https://support.apple.com/zh-cn/102445) 确认打开。
不要将损坏或恶意软件警告直接视为误报。

云端流程复用成功的 Build Matrix 产物，核对来源提交及安全门禁后校验原更新签名，
检查应用 ID、版本、架构、资源及图标，再对最终 .app 临时签名、制作 DMG 并验证挂载内容。
生成新的更新压缩包后重新签名。Apple 芯片与 Intel 包分别在对应架构的 Mac runner 上检查启动。
这属于安装包与启动验收，不代表已经使用真实账号验证所有外部服务。

Google/Gemini/Antigravity 的自有 OAuth 构建凭据仍未配置，与 Windows 版的已知限制相同。
现有 `release.yml` 的 Developer ID、公证检查仍保留；`macos-packages.yml` 单独标注并生成临时签名包。
