# 聚灵 1.3.74 增量同步与 Windows 发布 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 同步上游 1.3.74 的真实功能，保留聚灵皮肤与隐私策略，备份覆盖本地安装并在授权允许时公开独立更新。

**Architecture:** 以固定的上游 1.3.73（5330f75ae6b3c39fbd72f528ac2188207047d49a）和 1.3.74（054867e5d6f15ba03c48796bc97cdb2cd359247e）做三方增量合并，不重新运行旧版全量迁移脚本。保留当前 Tauri/Rust/Go 架构、独立 updater 公钥及数据兼容；所有安装和冒烟测试只针对聚灵副本，绝不运行或修改原版。

**Tech Stack:** React/TypeScript、Tauri 2/Rust、Go sidecar、NSIS、Node.js、GitHub CLI。

### Task 1: 固定证据并备份

- 读取上游 release 与 tag 对应 commit，核对本机原版文件版本与 SHA-256，不执行原版。
- 保存源码 HEAD 的 git archive 和现有稳定安装目录到 `../维护/升级备份-20261025/`，目录已存在时不覆盖已有备份。
- 生成 `../维护/sync-v1.3.74/` 中的差异和合并报告。上游本次共 188 文件，包含会话索引修复、Session ID 映射、压缩会话、安全恢复、客户端启动、额度/OAuth 和 Rust/Go 协议修复。

### Task 2: 增量迁移并验证

**Files:** 上游改动映射到 `crates/juling-core/`、`sidecars/juling-cliproxy/`、`src-tauri/src/`、`src/` 和 `tests/` 的对应文件；不覆盖聚灵专有皮肤、推广禁用 stores、OAuth 自有配置、公钥、安装隔离和配置保护策略。

1. 基于 v73/v74 仅对上游发生变动的文件进行标准三方合并。新增文件重命名为聚灵内部命名；第三方许可及供应商代码不做品牌替换。冲突必须逐个审核，不默认用上游覆盖本地。
2. 导入上游本次回归测试，在源码级审计新命令与调用链完整性、Session ID 开关默认值和用户确认逻辑。保持 UI 展示 S1.0。
3. 更新 `package.json` 真实版本为 1.3.74，执行 `npm run sync-version` 并核对 Cargo/package 锁文件，不改依赖版本。
4. 运行 `npm test`、`npm run test:release`、`npm run test:codex-parity`、Rust core 与桌面相关单元测试、Go 测试；桌面 Rust 测试如需 Windows common-controls 清单，仅处理测试副本。预期零非已知平台限制失败。
5. 检查第三方品牌/推广 URL、公告、遥测与 updater 源，保留必要协议 ID 和法定归属，不修改账号、API endpoint、模型偏好或密钥。

### Task 3: 构建、签名和覆盖安装

**Files:** `src-tauri/tauri.conf.json`、`scripts/release/`、`docs/releases/v1.3.74.md`、`docs/windows-usage.md`。

1. 复用私有目录现有 updater 私钥，执行 `node scripts/tauri.cjs build --bundles nsis --ci`。密钥和 DPAPI 解密密码仅进入子进程环境，绝不输出、提交或上传发行资产。
2. 将安装器与签名规范化到新的 `../维护/release-v1.3.74/assets/`，生成 Windows-only manifests、便携 ZIP 和 SHA256SUMS。验签并用篡改负例证明校验生效。
3. 解出自己的 NSIS 到新的目录，核对完整资源。确认聚灵进程与安装目标精确路径后，覆盖 `../聚灵-本地版`；不用自动启动正式账号的参数。
4. 核对注册表版本、快捷方式、文件哈希及原版未变；用全新 `JULING_TOOLS_DATA_DIR` 和 WebView profile 隔离启动验收，不触碰正式账户。

### Task 4: 发布与公开验收

1. 审核 diff 和显式提交清单，排除账号、凭据、日志、截图及构建文件；正常提交与推送分支、标签，不强推。
2. 若 workflow scope 未恢复，继续保留本地完整成果，明确报告阻碍；不得声称用户检查更新已可用。
3. 权限恢复后，创建 draft Release，上传完整 NSIS、签名、便携包、更新清单和校验和，核对后公开为 latest。
4. 匿名下载验证 manifests 指向 1.3.74，安装包 hash 和 updater 签名均一致；记录公开 URL 与验收结果。Windows Authenticode、自有 Google OAuth 和未实测真实账号的限制保持如实披露。
