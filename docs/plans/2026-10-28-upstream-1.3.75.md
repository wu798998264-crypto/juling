# 聚灵 1.3.75 增量同步 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将聚灵升级到原版最新稳定版 1.3.75 的功能能力，保留独立皮肤、绿色品牌、S1.0 展示、广告过滤和独立签名更新。

**Architecture:** 用固定上游 1.3.74（054867e5d6f15ba03c48796bc97cdb2cd359247e）与 1.3.75（2cfe5e51314bfc0bf70bdda1ba08aed82c7dc8bf）做三方增量比较，在已确认 tracked 干净且完成归档备份的聚灵工作目录执行。维持 React/Tauri/Rust/Go 的运行链路，不对原版 EXE 做动态操作，不迁移或替换用户真实账号、API、模型与密钥配置。

**Tech Stack:** React/TypeScript、Tauri 2/Rust、Go sidecar、NSIS、Node.js、GitHub CLI。

---

用户要求更新聚灵，沿用此前已确认的备份、覆盖安装和独立仓库发布流程。上游源仅只读比较。上次工作流要求的专用 superpowers 子技能未安装，使用本机 Code 与 Git 流程执行，不派发未经用户请求的子代理。保留 `.playwright-cli/`、`output/` 和 `scripts/maintenance/` 等已有未跟踪内容。

### Task 1: 固定版本与备份

**Files:** `../维护/upstream-v1.3.75/`、`../维护/升级备份-20261028/`、`../维护/sync-v1.3.75/`。

1. 用官方 Release、annotated tag 和 commit 交叉确认最新稳定版，不采用 main 的未发行提交。
2. 保存当前 HEAD 93505f3769c08eb98c489143e063d758a112d832 的源码 ZIP 和完整安装目录；验证备份 EXE 与当前安装哈希一致。
3. 保存原版 SHA-256，只读原版，不启动、关闭或修改它。记录当前聚灵进程，测试与构建不打断正式实例。

### Task 2: 三方迁移与聚灵适配

**Files:** 170 项上游差异对应的 `src/`、`src-tauri/src/`、`crates/juling-core/`、`sidecars/juling-cliproxy/` 和 `scripts/`。

1. 先在维护目录生成机械三方合并候选与逐文件报告，再使用补丁应用已审核结果；冲突逐个处理，禁止用上游全量覆盖。
2. 新增背景设置、本地图片、渐变、强度/模糊/位置与立即保存，适配聚灵现有皮肤；不修改账号卡片的原有交互。
3. 同步 Terra 模型与费用估算、Codex 额度到期缓存/提示、Antigravity 模型分组及兼容性修复。
4. 同步请求取消隔离、协作工具命名空间、官方模型路由、Kiro JSON 授权、Claude Gateway 保留用户设置、运行中会话索引修复和 Windows 启动/缺失路径恢复。
5. 原版供应商推广皮肤只保留必要结构兼容，展示使用聚灵通用主题，不引入原版品牌、推广跳转、公告或赞助路由重写。供应商真实 API 地址、协议标识和第三方许可不做盲目替换。
6. 保留 Windows 新备份可写刷新句柄修复、广告/公告/反馈后端禁用、独立 updater 公钥和自有 OAuth 凭据策略。
7. 将内部真实版本同步到 1.3.75；界面产品版本继续 S1.0。补写 `docs/releases/v1.3.75.md`、`docs/windows-usage.md` 与 README 基线说明。

### Task 3: 回归验证

**Files:** 上游新增/修改测试及本次新增聚灵策略回归。

1. 运行 `npm run typecheck`、`npm test`、`npm run test:release`、新增开发进程与客户端注入测试。
2. 执行 Rust core、桌面编译及定向单元测试：运行中索引修复、保留聊天记录/并发变化、Gateway 配置保护、请求取消/错误分类、命名空间、模型/计费、额度与 Windows 路径恢复。
3. 执行 Go 主模块及新增 Terra/取消回归；第三方相关包定向测试。若遇既有平台失败，明确隔离、按旧基线复现，不放宽业务断言掩盖。
4. 用隔离数据与 WebView 配置检查新增背景 UI、缺失路径弹框和滚动遮挡；不加载真实账号、不发送付费模型请求、不改用户 Provider。
5. 检查 UI 广告字符串、远程后端与 updater URL，保留必要来源/许可；对独立公钥和本地品牌做静态回归。

### Task 4: 构建、覆盖、发布

**Files:** `../维护/release-v1.3.75/assets/` 与 `../维护/聚灵-v1.3.75-同步与覆盖验收.md`。

1. 使用现有独立 updater 私钥构建 Windows x64 NSIS，密钥只在构建子进程环境中使用，不输出或放入同步盘。
2. 从最终安装包提取完整资源，制作便携 ZIP、三个更新清单和 SHA256SUMS；验签和篡改负例必须通过。
3. 覆盖前精确核对目标路径与聚灵进程。若正式实例仍在使用或有未完成操作，先向用户确认关闭，禁止强制终止无关进程。
4. 覆盖安装后逐项比对程序资源，核对版本、快捷方式及安装期间配置文件哈希；隔离启动测试后只关闭本任务实例。
5. 审核提交清单并正常提交/推送 main 和 v1.3.75，不强推、不覆盖已公开的旧版本。先上传 draft 的完整 7 项资产再公开为 latest。
